## CRITICAL

### C-1 · Ingestion pipeline crashes on every timestamped reading
- **Location:** `mqtt/client.py:97` → `tasks/process_reading.py:92`
- **Status:** `FIXED` — dispatch serializes with `payload.model_dump(mode="json")` and `_parse_time` accepts `str | datetime` (returns the datetime as-is, normalizing tz to UTC). Covered by `tests/test_process_reading.py`.
- **Issue:** `process_reading.delay(payload.model_dump())` sends `time` as a Pydantic `datetime`. Kombu's JSON codec round-trips it into a `datetime` object in the worker, then `_parse_time` runs `datetime.fromisoformat(value.replace("Z", "+00:00"))` on a `datetime` → uncaught `TypeError` (only `ValueError` is caught). The task fails, the message is acked (default `acks_late=False`), and the reading is silently dropped. Only payloads that omit `time` survive.
- **Fix:** Serialize at dispatch with `payload.model_dump(mode="json")`, or make `_parse_time` accept both `str` and `datetime`.

## HIGH

### H-1 · Fuzzy score stuck at 20 ("Good") whenever temperature is missing or 0°C / sub-zero
- **Location:** `tasks/process_reading.py:57-61` · `fuzzy/membership.py:61-76` · `fuzzy/tsukamoto.py:37-38,52-69`
- **Status:** `FIXED` — `temp_low` is now a shoulder (`trap(0,0,15,35)`) so `t==0` / sub-zero fires a rule; missing temperature is substituted with `25.0` °C (domain midpoint).
- **Issue:** `process_reading` substitutes a missing temperature with `0.0`, but at `t == 0.0` all three temperature memberships are 0, so **zero rules fire** and the engine returns `DEFAULT_SCORE = 20.0`. Sub-zero readings clamp to 0 as well. Result: heavy pollution (e.g. PM2.5=250) is stored with fuzzy score 20 while the same row's `aqi` correctly reports ~300/Unhealthy — the two columns contradict each other.
- **Fix:** Give "Low" a shoulder at the domain edge (`temp_low = trap(t, 0, 0, 20, 30)`), and/or substitute a mid-domain neutral value (e.g. `25.0`) instead of `0.0`. Update `tests/test_fuzzy.py:78` which asserts `temp_low(0) == 0.0`.

### H-2 · AQI extrapolates past 500 for concentrations above the top breakpoint
- **Location:** `tasks/aqi.py:44-57`
- **Status:** `FIXED` — `_aqi_for` clamps the concentration to `[0, top C_hi]` before interpolating, so AQI cannot exceed 500.
- **Issue:** `_subindex` clamps the band index but not the value; the last band interpolates with the raw concentration. PM2.5=1000 → AQI ≈898; PM10=2000 → AQI ≈2052. The MQTT validator allows pm up to 2000 and PMS5003 sensors can report up to 1000 µg/m³, so this is reachable in practice and breaks the documented 0–500 range (`docs/database.md`).
- **Fix:** Clamp inside the band before interpolating: `c = min(concentration, hi)`.

### H-3 · Node spoofing: reading path trusts body `node_id` instead of the topic id
- **Location:** `mqtt/client.py:42-104,170-187` · `mqtt/validator.py:48`
- **Status:** `FIXED` — `_handle_reading` overrides the payload's `node_id` with the topic id (`data["node_id"] = node_id`) **before** validation/dispatch; the body `node_id` is optional and pattern-checked (`^[A-Za-z0-9_-]{1,50}$`) in the validator. The reading path is now consistent with `_handle_status`.
- **Issue:** The `node_id` parsed from `air/node/{id}/reading` is never cross-checked or forwarded; `process_reading` attributes the reading by the body's `node_id`. Any MQTT client can publish `air/node/ESP32-01/reading` with body `{"node_id":"ESP32-02",...}` and pollute ESP32-02's readings/AQI/anomaly/Redis cache. A compliant device that relies on the topic and omits body `node_id` is silently dropped.
- **Fix:** Make the topic id authoritative (e.g. `{**data, "node_id": node_id}` before dispatch) or pass `node_id` as a separate task arg and reject mismatches. (Covered by `tests/test_mqtt.py` authority + topic-only round-trips.)

### H-4 · MQTT TLS fails open when cert files are missing
- **Location:** `mqtt/client.py:219-258,334-344`
- **Status:** `FIXED` — `_configure_tls` raises `RuntimeError` when `MQTT_USE_TLS=True` but any required cert setting is unset/empty *or* its file is unreadable; `start()` additionally fails closed if TLS was requested but `_tls_configured` is false. (Covered by `tests/test_mqtt.py` H-4 cases.)
- **Issue:** With `MQTT_USE_TLS=True` but any of `MQTT_TLS_CERT`/`MQTT_TLS_KEY`/`MQTT_CA_CERTS` missing, `_configure_tls` logs a warning and returns without calling `tls_set`; `start()` connects anyway → plaintext on a dual-protocol broker, or an infinite reconnect loop against a TLS-only broker.
- **Fix:** In production, raise on missing certs so the process refuses to start; otherwise refuse to connect when TLS is requested but not actually configured.

### H-5 · Rate-limit bypass + victim-bucket poisoning via spoofed `X-Forwarded-For`
- **Location:** `api/rate_limit.py:36-41`
- **Status:** `FIXED` — `_client_ip` now derives the bucket key from `request.remote_addr` only (Quart's trusted `Remote-Addr` header), never the client-supplied XFF. (Covered by `tests/test_rate_limit.py`.)
- **Issue:** `_client_ip()` trusts the client-supplied first `X-Forwarded-For` entry. An attacker gets a fresh bucket per request (bypassing the 200/min limit), can burn a victim's bucket (DoS), and can mint unbounded Redis keys.
- **Fix:** Derive IP from `request.remote_addr` only, or use a trusted-proxy-configured header (`X-Real-IP`/`Forwarded`). Never treat the first XFF entry as authoritative.

### H-6 · bcrypt (~500 ms, cost 12) runs synchronously on the Quart event loop
- **Location:** `api/auth.py:104,156,160` · `api/profile.py:129-135`
- **Status:** `FIXED` — every cost-12 `hash_password` / `bcrypt.checkpw` in both blueprints is wrapped in `await asyncio.to_thread(...)`, so ~500 ms bcrypt work runs off the Quart event loop.
- **Issue:** Every login/register/change-password blocks the whole event loop for ~0.5 s, freezing in-flight requests (readings, forecast). Two concurrent logins stall the API ~1 s — violates the <200 ms p95 target (`docs/security.md`) and enables a trivial availability DoS.
- **Fix:** `await asyncio.to_thread(bcrypt.checkpw, ...)` (and for `hash_password`). Consider making `_DUMMY_PASSWORD_HASH` lazy so startup isn't slow.

### H-7 · Production secret guard is incomplete
- **Location:** `config/__init__.py:13-28,100-125` · `.env.example:36`
- **Status:** `FIXED` — the shipped `SECRET_KEY` placeholder (`change-me-to-a-random-secret`) is in `_DEV_SECRETS`; production additionally enforces ≥32 bytes and ≥5 distinct characters for both `SECRET_KEY` and `JWT_SECRET`. (Covered by `tests/test_config.py`.)
- **Issue:** The `_DEV_SECRETS` blocklist misses the shipped `.env.example` `SECRET_KEY` placeholder (`change-me-to-a-random-secret`), so production can boot with a publicly-known session-signing key. The guard also accepts `JWT_SECRET=""` / `"a"` — any non-blocklisted value passes, enabling forged HS256 tokens.
- **Fix:** Add the placeholder to `_DEV_SECRETS`; enforce a minimum length/entropy (≥32 bytes) for `JWT_SECRET` and `SECRET_KEY` in production; ideally derive the blocklist from `.env.example` so the two can't drift.

## MEDIUM

### Fuzzy engine
- **M-1 · Membership functions don't form a proper partition → pollution non-monotonicity** — `fuzzy/membership.py:23-32,61-76,81-96,101-116`. Adjacent terms don't cross at 0.5, so Σ terms < 1 in transition bands. At T=8.5, H=0, raising PM2.5 35→40 **lowers** score 42.75→42.0; at H=20,P=10, T 20→27.5 drops 60.0→37.5. *Fix:* reshape MFs so adjacent terms cross at 0.5, add a partition unit test (Σ terms ≈ 1). — **Status: `FIXED`** (terms cross at 0.5; Σ≈1 partition confirmed by a 0.1-grid sweep; both documented regressions resolved — `infer(8.5,0,35)=60` == `infer(8.5,0,40)=60`). Residual: PM2.5→score is not *fully* monotonic — up to ~9-pt transition-band dips remain (structural to the Tsukamoto weighted average; see N-10). The "full (T,H) monotonicity sweep" test name overstates what it checks (6 discrete p-values).
- **M-2 · NaN sensor values silently clamp to domain tops → worst-case score** — `fuzzy/membership.py:18-20` (`min/max` with NaN return the non-NaN bound). `infer(nan,20,250) → 100.0`, `infer(20,50,nan) → 77.5`. Reachable because `mqtt/client.py:71` uses non-strict `json.loads` and `_to_float` passes `float('NaN')` through. `None` inputs raise an uncaught `TypeError`. *Fix:* reject non-finite values at the `infer()` boundary; treat NaN as missing in `process_reading`. — **Status: `FIXED`** (`infer()` now raises `ValueError` for non-numeric/non-finite inputs; `process_reading._valid_float` maps NaN/Inf to `None`/missing).

### Celery tasks
- **M-3 · Aggregation bucket timezone drift** — `tasks/aggregation.py:43-44,57`. The UTC `[start,end)` window is computed in Python but `date_trunc('hour', time)` truncates in the **DB session** timezone → one UTC hour can split into two buckets (e.g. UTC+5:30). *Fix:* `SET TIME ZONE 'UTC'` in the task or `date_trunc('hour', time AT TIME ZONE 'UTC')`. — **Status: `FIXED`** (`tasks/aggregation.py` buckets with `date_trunc('hour', time AT TIME ZONE 'UTC') AT TIME ZONE 'UTC'`).
- **M-4 · Alert dedup suppresses escalations and is racy** — `tasks/alerts.py:98-116`. Any unacknowledged alert for node+aqi blocks *all* new alerts — an unacknowledged warning silently suppresses a later critical. Check-then-insert isn't atomic and there's no unique constraint → double-insert under two workers. *Fix:* only suppress when an alert of ≥ the new severity exists; add partial unique index `(node_id, parameter) WHERE acknowledged_at IS NULL`. — **Status: `FIXED`** (dedup upserts only when `existing_rank < new_rank`; partial unique index on `models/alert.py` + migration `1785940433799_add_alerts_partial_unique.py`).
- **M-5 · Alerts fire from stale readings (offline nodes)** — `tasks/alerts.py:50-58,93-96`. `_latest_aqi` never bounds recency, so an offline node with AQI160 re-fires critical alerts on every beat run forever. *Fix:* bound to a recency window (e.g. `time >= now() - interval '10 minutes'`). — **Status: `FIXED`** (`_AQI_RECENCY = 10 min` filter in `_latest_aqi`).
- **M-6 · No `acks_late`: worker crash loses readings; PK-duplicate guard is dead code** — `celery_app.py:30-34` · `tasks/process_reading.py:196-220`. With `acks_late=False`, messages ack on receipt before commit; the `IntegrityError` duplicate path only fires on redelivery, which requires `acks_late=True`. *Fix:* `task_acks_late=True` + `task_reject_on_worker_lost=True`. — **Status: `FIXED`** (`celery_app.py` sets `task_acks_late=True`, `task_reject_on_worker_lost=True`, `task_acks_on_failure_or_timeout=False`).
- **M-7 · No backfill: missed aggregation hours never recover** — `tasks/aggregation.py:30-45`. `hourly_aggregate` only rolls up the single most recent complete hour; downtime/backlog across an hour boundary loses that bucket forever. *Fix:* iterate back over all complete-but-unaggregated hours or track a watermark. — **Status: `FIXED`** (aggregation computes the earliest un-aggregated hour + watermark and rolls up the whole window).

### MQTT
